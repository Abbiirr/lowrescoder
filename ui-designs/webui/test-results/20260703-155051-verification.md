## What the live e2e actually proves

It spawns the mock harness server (real WebSocket) and loads the REAL client stack
(rpc.js + events.js + demo.js + app.js + wiring.js) headless in Deno, then drives one
full turn through the UI seams and asserts the rendered state at each stage:
connect → session.list populates sidebar (5) → command.list populates skills →
chat send → on_chat_ack user row → on_token streamed answer → on_tool_call act rows →
server-initiated on_tool_request → approve → pending cleared → on_done finalizes answer
("All tests green") → on_cost_update updates meter (64%) → config.set model reflected via
on_status. 10/10.

## Bugs found and fixed during verification

1. **Reducer dedup caught a mock modeling error**: the mock reused one event `id` for all
   streamed `on_token` chunks, so the reducer (correctly, per agent-events.md) dropped
   every chunk after the first. Fixed the mock to give each token a unique event id; the
   reducer groups tokens by the in-progress answer row, not by id.
2. **Windows orphan servers**: killing `uv` did not kill its `python` child, leaving the
   port held. Fixed by (a) tree-killing via `taskkill /F /T /PID` in the e2e cleanup and
   (b) a `--max-seconds` watchdog in the mock as a backstop. Confirmed no orphan after runs.
3. **pytest teardown**: `CancelledError` is a `BaseException` in 3.11, so `suppress(Exception)`
   missed it — fixed the test client's close().

## Protocol assumptions (must be verified against the real backend)

- `on_tool_request` / `on_ask_user` are server-initiated JSON-RPC *requests* the client
  answers with a response carrying `{decision: allow|deny}` (+ `answer` for ask_user).
- Streamed `on_token` events each have a unique event `id`; tokens are grouped into the
  current in-progress answer row (not keyed by id).
- Request/result envelopes (param and result field names) are this repo's best reading of
  the method-name-level docs; `webui/backend/README.md` lists every ws_host assumption and
  `webui/mock-server.py` encodes the client-facing shapes. Verify vs `rpc-schema-v1` fixtures.
