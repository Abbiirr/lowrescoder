## Concerns

### Critical bugs in `/rollback` slash-command handler (`autocode/src/autocode/app/commands.py:1377-1451`)

**Bug 1 — `/rollback restore <id>` is broken (cannot actually restore via the documented contract syntax).**

At line 1402-1403, the handler does:
```python
if arg and arg != "--last":
    cp = cp_store.get_checkpoint(arg)
```

When user types `/rollback restore <id>`, `arg = "restore <id>"`. `cp_store.get_checkpoint("restore <id>")` does a literal SQL lookup for an ID equal to the string `"restore <id>"`, which never matches any real checkpoint ID. The user gets `Checkpoint not found: \`restore <id>\`` and never reaches the restore branch.

The `if not arg.startswith("restore"): return` at line 1426 only fires AFTER `get_checkpoint(arg)` already returned None at line 1404. The "restore" subcommand parsing must happen BEFORE the get_checkpoint call.

**Suggested fix:** parse the subcommand at the top of the handler:
```python
if arg.startswith("restore "):
    is_restore = True
    arg = arg.removeprefix("restore ").strip()
elif arg == "--last":
    ...  # existing flow, then set arg = latest.id
else:
    is_restore = False
```
Then route on `is_restore` after `cp = cp_store.get_checkpoint(arg)`.

**Bug 2 — `/rollback --last` only previews, does not restore. Contract violation.**

`docs/features/checkpoints-restore.md` and the §4.G1 checklist both state: `/rollback --last → restore the most recent pre-tool checkpoint`. The current flow at lines 1394-1400 + 1402-1427:

1. `arg == "--last"` enters the `--last` block, sets `arg = latest.id`
2. Falls through to the `if arg and arg != "--last":` block
3. Looks up the checkpoint, shows preview, returns at line 1427 because `arg.startswith("restore")` is False (arg is now a plain ID)

So `--last` only previews, never restores. The current message "Use `/rollback restore {cp.id}` to confirm rollback" suggests `--last` is preview-only, but that contradicts the contract.

**Suggested fix:** in the `--last` branch, set a flag (e.g., `auto_restore = True`) and skip the preview-only return at the bottom; or short-circuit into the restore branch directly. Implementation choice — both are fine as long as `--last` actually restores.
